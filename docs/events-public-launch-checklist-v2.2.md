# AI CoCreate Life 公益活动：发布前运营与安全清单 v2.2

> 适用于 /events 活动报名页面。当前仅在 GitHub 开发分支及 Vercel Preview，未经最终发布批准不得合并到生产环境。

## 1. 人数管理：由管理员确认，不自动占位

**表：** Airtable → AI Personality Test Data → Event Registrations。

**状态（Status 字段输入固定英文值）：**
- `Pending`：申请已收到；未确认席位。API 只创建此状态。
- `Confirmed`：组织者已核对并确认席位；已发送确认通知后再记录。
- `Waitlisted`：名额不足，进入候补；需明确通知。
- `Cancelled`：报名者取消或组织者取消。

**人数核算：** 先与场地核实当场最多容纳人数及主讲、主持、志愿者占用的席位数。对公众的可确认名额 = 实际安全人数上限 − 工作人员预留名额 − 其他预留。**不可直接将场地约45人视为45个可报名席位。**

**每天或每次活动前查看：** 按 `SubmittedAt` 排序。先处理 `Pending`，人工审核，然后将状态改为 `Confirmed` 或 `Waitlisted`。对相同邮箱核查是否存在重复项。未有真实日期/地点前，通常应保持 Pending，不发送含未经落实日程的确认消息。

**通知记录：** 表中新增 `NotificationStatus`（Not Sent / Sent / Failed）、`ContactedAt`（ISO日期时间文本）、`AdminNotes`。**只在邮件真正发出后**标为 Sent；未自动发送任何邮件。人工确认邮件可由您日常邮箱发送，减少系统故障。

## 3. 隐私与资料最小化

- 必填只有姓名、邮箱、身份与针对本活动的明确同意；微信、孩子年级、关心话题和问题均为选填。
- 申请资料只在服务端写入 Airtable 的活动独立表；不公布报名人名单；不将该信息自动加入营销、IEC、学生档案或社区。
- 使用同一 Airtable 工作区时按最小权限授权；不要给参与协办的人共享全部测试数据或完整工作区权限。
- 正式公开前确定并写明：资料删除联系邮箱；保存周期（可讨论活动后90天清理）；是否允许活动照片及现场记录，需单独授权（不得由报名同意默认涵盖）。
- 正式发布前检查 Airtable/邮件平台的适用隐私条款和处理关系。本实施记录不是法律意见。

## 4. 技术安全与限制

已加入：
- POST + JSON 限制；输入类型、字段长度、选项集合、邮箱和必填同意验证；8KB请求上限
- 当 Origin 存在时进行同域来源核验；无跨域 CORS 开放；不公开报名数据读取接口
- 隐藏蜜罐字段；服务端密钥只从 Vercel 环境变量读取
- 删除旧 `api/test-env.js` 中返回部分敏感密钥信息的诊断接口

仍需完成：
- 适当的速率限制/机器人挑战（可在Vercel/边缘WAF启用，或后续使用Turnstile）
- 确认并发重复报名和恶意批量请求不会造成重复记录：现有顺序去重不是事务型保证
- 邮件送达性与人工回复管理
- 活动日期、时间、场地地址、停车/无障碍信息、容量与取消规则
- 一轮用户手机浏览器（尤其微信内置浏览器）实测
- 发布前隐私联系途径与资料留存规则

## 5. 正式发布决策门槛
1. 主办方确认日期/时间/地点/可用座位和组织者联系方法。
2. 预览版本提交有效报名并读回；无效请求被拒绝；测试记录删除。
3. 通过反滥用、隐私说明与移动端检查。
4. 核实已有测评/支付流程回归无误。
5. 用户明确批准后，才允许PR合并main并在生产Vercel配置报名专用变量。

**禁止把PR Preview的可用性等同于正式上线。** 活动报名本身也不等于商标所申请的在线会员社区实际使用。
